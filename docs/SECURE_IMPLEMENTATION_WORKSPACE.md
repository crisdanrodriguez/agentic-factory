# Secure implementation workspace foundation

MVP-02B.1 adds a private, per-Run source staging lifecycle. Its binding includes the organization, project, GitHub installation/repository identity, exact Git commit, WorkItem and revision, Run, plan and policy revision, source snapshot, environment fingerprint, `agent.edit` capability, and sandbox limits. The caller supplies the owner-trusted project/repository scope; every lifecycle operation checks it. A mismatched binding cannot inspect, cancel, or remove another workspace.

`LocalPinnedGitSource` reads an owner-selected local bare repository with the exact expected HTTPS origin and commit object. It uses Git object reads only, with no checkout, submodule expansion, hooks, filters, setup scripts, or network operation. Symlinks, submodules, binary or oversized files, invalid paths, and excess file counts fail closed. Repository installation and numeric ID are trusted owner configuration values; local Git metadata alone cannot attest those GitHub IDs. MVP-02B.2 must establish the owner-approved commit and repository provenance before constructing the binding.

Preparation writes a mode-0700 Run directory and mode-0600 files under an owner-private root. A manifest records the complete binding, digests, and preparation phase. Validation detects changed files, unexpected entries, unsafe permissions, and symlinks. Cancellation and cleanup remove only the binding-derived Run directory. Recovery validates prepared workspaces and removes journaled interrupted preparations; an unjournaled or unknown resource requires operator review. Source files are staged as data and can be handed to the reviewed Linux sandbox tmpfs. The host staging path is never an agent workspace.

The existing reviewed Docker runtime enforces `network=none`, read-only root, dropped capabilities, seccomp/AppArmor, cgroup CPU/memory/PID limits, and tmpfs workspace and output size. The broker enforces execution deadlines and cleanup. Hosted integration checks the isolation controls while staging synthetic source, without starting an implementation agent. No capability grant for real `agent.edit` execution is issued in this increment. The sandbox broker and PostgreSQL workflow authorization remain unchanged.

MVP-02B.2 must bind the prepared source and exact Run authorization into a one-use sandbox grant, verify the checkout/executable and working directory at execution time, prevent host credentials from entering the agent environment, enforce artifact quotas and interruption cleanup during agent activity, and record evidence. Real implementation remains disabled.
